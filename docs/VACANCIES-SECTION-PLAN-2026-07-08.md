## Структура страниц

**Hub (~2000 слов):** H1 «Актуальные вакансии в агентстве OFM Model Agency» + trust-строка «6 открытых вакансий · Обновлено [живая дата] · города + удалённо» → ЛИСТИНГ карточек первым экраном (роль + город + вилка $ + дата `<time>` + CTA) → якорная навигация → SEO-полотно: PAA дословно в H2 («В чем заключается работа Онлифанс?», «Как устроиться?», «Можно ли реально заработать?»), блок «для мужчин», блок городов → FAQ 6–8 (FAQPage-schema).

**Ролевая (1000–1500 слов):** H1 + сводка-плашка (город/вилка/формат/видимая дата = дате в JSON-LD — требование Google) → Обязанности → Требования → Оплата и график (чатер: ставка+% с примером расчёта; модель: 20–30% от gross С реинвест-обоснованием) → «Как выглядит рабочий день» (150–250 слов нарратива — уникализация) → «Как проходит отбор» → FAQ роли → CTA-форма.

**Перелинковка:** hub ↔ роли ↔ чатер-пиллар (блог) ↔ /join ↔ городские посты блога; nav.vacancies в messages/*.json, футер, блок на главной.

## ⚙️ Автоматика свежести (ядро)

**Скрипт `scripts/rotate-vacancies.mjs`** (`npm run vacancies:rotate`):
1. Kill-switch: `VACANCY_ROTATION=off` → выход
2. Честная ротация: datePosted сдвигается ТОЛЬКО как реальное переопубликование, цикл 21–28 дней **пер-slug с hash-джиттером** (даты никогда не двигаются пачкой — анти-«fake reposting»), максимум 2–3 вакансии за прогон
3. validThrough всегда = datePosted+30д; вакансии с истекающим validThrough (<5 дней) ротируются вне лимита — разметка не протухает
4. dateModified обновляется для видимой даты «Обновлено» и sitemap lastModified
5. Диф строго только dates.json — иначе аварийный стоп

**Workflow `.github/workflows/vacancies-rotate.yml`:**
- cron `0 5 * * 1,4` (пн/чт ~08:00 Киева) + workflow_dispatch; permissions только contents:write; concurrency-замок; timeout 15 мин
- Шаги: checkout → node rotate → guard «диф только dates.json» → `npm run build` (проверка сборки ДО пуша) → commit `chore(vacancies): rotate dates` → push → Vercel сам деплоит → Telegram-отчёт (по паттерну seo-alerts)
- Kill-switch №2: repository variable `VACANCY_ROTATION=off` — выключение без коммита
- Откат: git revert изолированного коммита
- **Внедрение поэтапно: сначала workflow_dispatch-only (ручной прогон 1–2 раза, демо владельцу) → cron включается отдельным коммитом после явного «да»**

Риски закрыты: fake-reposting (частичная ротация + живые вакансии + честные validThrough; мониторинг GSC → Enhancements), лимиты Vercel (+2 деплоя/нед — ничто), упавший билд не роняет прод.
